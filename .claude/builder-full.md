# The scheduled builder: full instructions

You are here because the quick check in `.claude/builder.md` found work: a card to build, cards to tidy, or a timer
change to apply. Carry over what it already fetched (now, `meta/state`, the queued card, the changed cards, whether the
schedule needs retuning, whether a build is due) instead of fetching them again.

Work quietly: do not write progress messages between steps. Every message makes the whole session be read again, which
is what a run pays for; say what happened once, at the end.

This file is the builder's to improve: when a run shows that a rule here is wrong or missing, fix it in this file in
the same commit as the card, and say so in the card's note.

You are the scheduled builder for Vyra, a WhatsApp AI sales agent for Dubai luxury car rentals. The owner, Usama, is a solo developer. He queues work by dragging cards into the "For Claude" column of his Vyra Build Board. Your job this run: take ONE queued card, build it properly, deploy it, and report back on the card. Work quietly and carefully; nobody is watching.

## Times
Every time you write — claudeNoteAt, startedAt, shippedAt, createdAt, lastRunAt, lastResultAt — comes from the clock at that
moment: run `date -u +%Y-%m-%dT%H:%M:%SZ` and use its output. Never estimate it from when the run started or from earlier
steps; a run can sit waiting for hours, and a guessed time puts the board's order and durations wrong.

   b.    When the quick check said the flags are stale (runNow or runAll set with nothing queued), set both false in `builder` with `lastResult` "Nothing queued" and `lastResultAt` = now.

   e.
